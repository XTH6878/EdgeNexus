# EdgeNexus Roadmap

## 1. 文档原则

本文区分“当前已实现”和“候选规划”。候选项不代表承诺版本、日期或交付顺序。

当前真实能力以 [INDEX.md](INDEX.md)、[Public-API.md](Public-API.md) 和源码为准。

## 2. 当前已实现基线

### 2.1 架构

- .NET 10。
- Domain / Application / Infrastructure / WebApi 分层。
- DI 与 BackgroundService。
- 进程内 Channel 生产者/消费者。
- 独立 Watchdog。

### 2.2 PLC

- 12 个 `ProtocolKind`。
- HSL 与 OPC UA SDK 驱动。
- 每设备异步循环。
- 批量读取计划。
- 状态防抖。
- 重连退避和抖动。
- 点位 Quality 与设备通信状态分离。

### 2.3 MQTT

- 单 Broker。
- 设备级消息。
- 分组 Topic 模板。
- 设备级 Payload 模板。
- 自定义字段。
- 设备通信状态系统 Tag。
- SQLite Store and Forward。
- 限速补发和死信。

### 2.4 配置

- 草稿。
- 校验。
- 原子发布。
- 历史版本。
- 删除。
- 回滚。
- Excel/CSV 导入。

### 2.5 运维

- Windows Service。
- systemd。
- Docker。
- Health。
- Metrics。
- JSON 日志。
- HTTP 写操作审计。
- 资源保护。

## 3. 规划优先级原则

候选功能按以下标准评估：

1. 是否降低现场停机风险。
2. 是否减少配置错误。
3. 是否提高可观测和可恢复性。
4. 是否保持跨平台。
5. 是否可通过自动化测试验证。
6. 是否引入新的故障域。
7. 是否有真实用户需求和数据。

### 4.1 LICENSE 选择

- 核对第三方依赖。

- 添加 `LICENSE` 和必要 NOTICE。

### 4.2 CI 基线

候选：

- Windows/Linux Release Build。
- xUnit 测试。
- Markdown 链接校验。
- public API 与文档覆盖检查。
- 依赖漏洞扫描。
- Docker 构建与健康冒烟。

### 4.3 发行包

候选：

- win-x64。
- linux-x64。
- 校验和。
- 升级说明。
- 数据库兼容说明。
- SBOM。

## 5. P0 候选：长期稳定验证

### 5.1 真实硬件兼容矩阵

按协议记录：

- PLC 型号。
- 固件。
- 协议模式。
- 点位类型。
- 扫描周期。
- 长稳时长。
- 断线恢复。

### 5.2 长稳压测

候选场景：

- 7×24 小时。
- 混合协议。
- Broker 断网 24 小时。
- 大 Outbox 恢复。
- 频繁配置发布。
- PLC 批量断线和恢复。
- 磁盘预警与恢复。

### 5.3 性能基线报告

不只写设备数，记录点数、周期、协议、硬件和延迟。

## 6. P1 候选：Polly 实际接入

当前只有 `Polly.Core` 依赖，未发现策略实际装配。

候选用途：

- SQLite 短暂 busy 重试。
- HTTP Watchdog 瞬态失败策略。
- 可控 MQTT 连接策略包装。

注意：不能让 Polly 与现有重连状态机重复重试，形成指数放大。

## 7. P1 候选：死信运维

当前可查询死信。

候选：

- 单条重放。
- 批量重放。
- 导出死信。
- 按错误筛选。
- 重放审计。
- 重放限速。

## 8. P1 候选：证书管理

候选：

- MQTT CA/客户端证书上传与校验。
- OPC UA 信任/拒绝证书查看。
- 证书到期预警。
- 私钥权限检查。
- 证书轮换流程。

## 9. P1 候选：多用户与 RBAC

当前主要是管理员角色路径。

候选角色：

- Viewer。
- Operator。
- Engineer。
- Administrator。

候选权限：

- 只读状态。
- 诊断。
- 编辑草稿。
- 发布/回滚。
- 用户管理。
- 安全配置。

## 10. P1 候选：API 限流

候选保护：

- 登录。
- 网络诊断。
- PLC 连接测试。
- MQTT 测试发送。
- Excel 导入。
- 版本预览。

当前配置快照和 SQLite 表由代码初始化。

候选：

- 显式 Schema Version。

- 升级前兼容检查。
- 旧配置导入转换。
- 迁移审计。

## 12. P2 候选：运行时插件系统

当前不存在。

候选目标：

- PLC 驱动插件。
- 北向 Transport 插件。
- 版本兼容检查。
- Manifest 和签名。

风险详见 [Plugin-Development.md](Plugin-Development.md)。

## 13. P2 候选：多 Broker

当前只有一个 MQTT 配置。

候选设计问题：

- 同一消息发送多个目标还是路由到一个目标。
- 每 Broker 独立 Outbox。
- 失败是否互相阻塞。
- Topic/模板是否按 Broker 配置。
- 状态和指标如何分组。

## 14. P2 候选：分组多设备聚合报文

当前每设备一条消息。

候选仅在服务器接口明确要求时评估：

- 聚合窗口。
- 最大设备数。
- 最大 Payload。
- 单设备失败语义。
- 重试粒度。
- 去重和顺序。
- 状态 Tag 排列。

稳定性默认仍优先设备级消息。

## 15. P2 候选：历史时序存储

当前没有历史数据库。

候选：

- InfluxDB。
- TimescaleDB。
- 本地短期环形历史。
- 降采样。
- 保留策略。
- 查询 API。

历史写入必须和 PLC 采集隔离，不能在采集循环同步写数据库。

## 16. P2 候选：数据转换规则增强

当前点位支持基础字节序、运算和小数处理。

候选：

- 枚举映射。
- 位拆分。
- 质量规则。
- 条件过滤。
- 组合 Tag。
- 脚本或表达式沙箱。

任意脚本会引入性能和安全风险，需要严格资源限制。

## 17. P2 候选：自动发现

README 旧描述曾提及自动发现，但当前源码没有完整通用自动发现系统。

候选按协议分别评估：

- OPC UA Browse。
- CIP Symbol browse。
- ADS Symbol browse。
- 局域网设备发现。

发现结果应进入草稿，不直接启动采集。

## 21. 不计划默认加入的高风险行为

- Web 页面直接写 PLC。
- 自动修改系统 IP。
- 无验证自动发布导入配置。
- 无限 Outbox。
- 无限并发连接。
- 用户任意 C# 脚本进程内执行。
- 关闭认证以方便现场访问。
- 在主进程内实现不可停止的 Watchdog。

## 23. 状态标记规则

建议未来使用：

- `Candidate`：候选讨论。
- `Designed`：设计完成，未实现。
- `In Progress`：源码开发中。
- `Implemented`：代码完成且测试通过。
- `Hardware Verified`：有真实设备记录。
- `Released`：进入正式发行版。

“Implemented”不能自动等同于“Hardware Verified”。

## 26. 协议候选进入基线的门槛

新协议不能只以“能连上”作为完成标准。进入已实现基线前至少满足：

- 协议参数由 Web 元数据生成。
- 设备参数和点位地址有后端校验。
- Excel 导入支持协议名称和专属字段。
- 连接测试调用真实驱动路径。
- 单点读取和部分失败语义明确。
- 支持取消、超时、断开和释放。
- 状态防抖与重连退避生效。
- MQTT 使用统一 `DeviceData/TagData`。
- Public API、PLC、Excel 和 FAQ 已更新。
- 有仿真或硬件验证记录。

## 27. MQTT 候选进入基线的门槛

- 采集线程不直接进行网络发布。
- 新消息先进入可恢复队列。
- Topic 与 Payload 分离构建。
- 预览和正式构建使用同一核心逻辑。
- 模板热更新不改变旧 Outbox Payload。
- Broker 断开不会停止采集。
- 重试有上限。
- 死信可观察。
- 补发有限速。
- TLS 和认证有测试路径。
- 指标和日志不泄露秘密。

## 28. Web 候选进入基线的门槛

- API 有认证和授权边界。
- 非只读请求有 CSRF 保护。
- 写操作进入审计。
- DTO 有输入范围校验。
- 页面不直接访问数据库或 PLC。
- SignalR 断开不影响核心运行。
- 新端点进入 WebAPI 文档。
- 新 public DTO 进入 Public API 文档。
- UI 变化有真实页面验证。
- 默认操作不会越过草稿发布边界。

## 29. 数据库候选进入基线的门槛

- Schema 创建或迁移可重复执行。
- 多步写入使用事务。
- 索引与查询模式有说明。
- 有容量和清理策略。
- 数据目录备份可恢复。
- 新旧版本兼容边界明确。
- Critical 资源状态下行为明确。
- 不在采集热路径同步执行慢查询。
- 配置文档和 Changelog 已更新。

## 30. 性能候选进入基线的门槛

- 有可复现基准。
- 有优化前后数据。
- 没有引入无限队列。
- 没有扩大单设备故障域。
- 取消和优雅关闭仍通过。
- Broker 断网和恢复仍通过。
- PLC 批量断线仍隔离。
- GC、CPU、内存和磁盘均有观测。
- 容量结论说明测试硬件和场景。

## 31. 文档自动化候选

当前文档已人工基于源码建立覆盖基线。后续可增加只读生成/校验工具：

- 扫描 Solution 项目和引用。
- 扫描 public 类型名称。
- 扫描 Minimal API 路由。
- 扫描 Options 和默认值。
- 扫描 HostedService 注册。
- 扫描 SQLite `CREATE TABLE`。
- 扫描 `ProtocolKind` 与地址目录。
- 扫描 Markdown 失效链接。
- 检查 Mermaid Fence。
- 检查所有专题链接回 INDEX。

自动化应生成差异报告，不应无审查覆盖人工解释段落。

## 32. 网络模块候选

当前网络模块只读取系统网卡并绑定用途，这是必须保持的边界。

可考虑：

- 网卡变化事件替代部分轮询。
- 绑定失效预警。
- 默认路由变化记录。
- DNS 解析诊断。
- 多目标路径对比。
- 网络质量趋势指标。

不规划：

- 自动修改系统 IP。
- 调用 `netsh` 或等价命令改地址。
- 在应用内维护第二套虚拟 IP 配置。

## 33. 配置协作候选

当前配置模型适合单管理员操作。未来多人维护可考虑：

- 草稿乐观并发版本。
- 字段级差异。
- 发布审批。
- 发布人和原因强制填写。
- 配置锁超时。
- 导入差异预览。
- 版本标签。
- 受控回滚审批。

协作功能不能让未发布草稿进入运行态。

## 34. 故障恢复候选

- Outbox 数据库完整性检查。
- 启动时配置快照一致性检查。
- 自动备份最近活动版本。
- 数据目录空间预测。
- Watchdog 恢复结果回传。
- 重启原因分类。
- 崩溃转储开关与保留策略。
- 受控安全模式启动。

安全模式应优先保护数据和管理入口，不应自动删除 Outbox 或配置。
